
# Bug 管理

项目根目录 `.flowcanvas/bugs.json` 保存唯一 Bug 列表。首页采用与测试用例一致的紧凑列表，显示标题及演示标记，支持搜索和行尾编辑。单击预览每个 Bug 的专属详情标签，双击固定；详情展示复核状态、描述、触发条件、可能影响、关联源码和关联测试用例。可从关联列表打开已关联的用例。右侧对话绑定该 Bug，支持多份历史。

AI 先调用 `bug_records(operation="inspect")`，按 `apply`、`begin_modify`、`update`、`end_modify` 登记或更新记录。写操作需要匹配最新的 `expected_revision`。记录可包含描述、触发条件、影响、证据和关联测试用例。源码绑定用稳定标识定位。

新记录默认为「待复核」。用户在 Bug 详情中可直接选择任一复核状态，在对话框中确认，并可填写补充说明。确认缺陷时可另外填写预期行为，已确认的记录也可直接补写预期。旧记录中的修复状态读取时归并为「已确认缺陷」，下次保存时使用归并后的状态。演示记录始终保持待复核。

演示数据只在用户明确要求时写入当前项目，不在打开页面时自动生成。列表单独统计真实记录与演示记录，演示详情始终显示“假设场景、未实际复现”的提示，不绑定虚构源码或用例。

在对话框的「测试与验证」中选择「同步测试用例关联」。工作流核对 Bug 与已登记用例的激励和断言，保留有依据的关联。待复核的 Bug 只同步关联。已有人工判定时，工作流依据明确规格修正用例断言和预期说明。已确认缺陷可使用人工填写的预期行为作为依据。证据不足时保留现状，并在结果中注明。默认只做静态验收。
